## Question

Are the settled choices — (1) raw `@xyflow/react`, (2) full-page editor, (3) notify → activity note — the right call for v1, or should any be reversed before implementation?

## Chairman’s verdict

### Where the council agrees

Proceed with React Flow DIY and a full-page editor. Keep notify behavior as an activity note for v1. Build the runner before canvas polish. Invest in English labels and templates.

### Where the council clashes

How hard to fix notify naming: migrate the enum vs display-label-only. **Resolution:** keep compatible storage if needed, but the UI must not present bare “Notify” — use **Log note** (or Notify + subtitle “logs a note on the contact”).

### Blind spots caught

- Missing `contact_id` in some trigger contexts → silent no-ops
- Condition true/false UX for non-technical users
- Template-first empty state
- Save-time graph validation (one trigger, max nodes)

### The recommendation

**Proceed with 1A, 2A, 3A.** Do not reverse canvas or shell. Honest UI labeling for the note action. Sequence: types + runner + deal_stage wire → full-page React Flow → templates.

### The one thing to do first

Implement `AutomationWorkflow` + headless multi-step/condition runner (notify → activity note), proven with a seeded fixture — **before** any React Flow UI.
