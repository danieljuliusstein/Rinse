---
name: overflow-x-clip/hidden implicitly creates a scroll container
description: Why setting overflow-x (clip or hidden) on a big wrapper div instead of html/body breaks window-level scroll assumptions (position:sticky, scrollIntoView, window.scrollTo).
---

Per the CSS overflow spec, if `overflow-x` is set to anything other than `visible` (including `clip`) and `overflow-y` is left as `visible`, the browser computes `overflow-y` to `auto` as well. This silently turns that element into its OWN scroll container, separate from the document/window.

**Why:** Hit this twice on the same project. First: `overflow-x-hidden` on the app's root div broke `position: sticky` sections (sticky needs its nearest scrolling ancestor to behave as expected — the sticky calculations got confused by the new inner scroll container). Switching to `overflow-x-clip` looked like it fixed the visual symptom, but it has the exact same auto-promotion behavior — it just wasn't obvious until later: `window.scrollY` stayed `0` and `window.scrollTo`/programmatic `scrollIntoView` calls appeared to do nothing to the visible page (they were actually scrolling the wrapper div, an invisible-scrollbar inner container, not the window), even though `document.documentElement.scrollHeight` looked normal-ish.

**How to apply:** If a page uses `position: sticky` sections, deep-link scrolling (`scrollIntoView`, `window.scrollTo`), or anchor-hash navigation, do NOT put `overflow-x-hidden`/`overflow-x-clip` on a large content wrapper div, AND avoid `height: 100%` on both `html` AND `body` together with `overflow-x: hidden`. The `height: 100%` chain locks body to viewport height; combined with `overflow-x: hidden` (which forces `overflow-y: auto`), body becomes the scroll container — window never scrolls, `window.scrollY` is always 0. Correct pattern for this project's `index.html`: `html { margin: 0; overflow-x: clip; } body { margin: 0; } #root { min-height: 100vh; }` — `overflow-x: clip` on `html` only (applies to viewport, no scroll-container side-effect), body has no height/overflow constraints, and `#root` uses `min-height` not `height`. Diagnostic tell: `window.scrollY` reads 0 right after `window.scrollTo(0, N)` even though `document.body.scrollHeight` is large.
